# VedaMilan Internationalization (i18n) & Localization (l10n)

## Architecture principle

```text
Business data / Astrology calculations  →  canonical codes & numbers
Presentation layer                      →  locale catalogs + formatters
User-generated content                  →  original preserved + optional translate
```

Language never changes Kundli math, Guna scores, payment amounts, or stored enums.

## Shell (production-ready)

- Locale registry: `src/lib/i18n/locales.ts` (`en hi sa mr es pt fr ar de bn ta`)
- Prefixed routing + middleware rewrite
- Message namespaces with English deep-merge fallback
- Client `useT()` / server `getServerT()`
- Chat optional translate; AI `aiLanguage` preference
- SEO alternates + sitemap

## Catalog platform (this iteration)

| Catalog                    | Purpose                            |
| -------------------------- | ---------------------------------- |
| `enums.*`                  | Gender, marital status, visibility |
| `compatibility.verdicts.*` | Decision summary codes             |
| `compatibility.moods.*`    | Score mood titles/blurbs           |
| `compatibility.reasons.*`  | Koota/Manglik reason codes         |
| `compatibility.kootas.*`   | Koota display names                |
| `compatibility.score.*`    | Match vs compatibility score copy  |
| `notifications.types.*`    | In-app notification templates      |
| `errors.codes.*`           | API error code → message           |

Helpers: `src/lib/i18n/catalogs/codes.ts`, `localize.ts`

Engines now emit:

- `strengthCodes` / `challengeCodes` (Ashta Koota / match blend)
- `decisionSummaryCode` (deep compatibility)

UI resolves codes at render time; English strings remain for backward compatibility.

## Dynamic content strategy

| Content                   | Strategy                                                               |
| ------------------------- | ---------------------------------------------------------------------- |
| System reasons / verdicts | Stable codes → catalogs                                                |
| Enums (gender, marital…)  | Canonical DB values → `enums.*`                                        |
| Notifications             | `type` + `data` → localized templates (EN title/body kept as fallback) |
| Chat / bio                | Original preserved; optional AI translate + cache                      |
| AI answers                | Respond in preferred language; Vedic terms via glossary                |
| Astrology numbers         | Never localized as different values — only labels                      |
| Payments                  | Server plan → currency/amount; display via `Intl`                      |

## Performance

- Per-locale JSON dynamic imports
- Namespace merge only for active locale
- No all-languages client bundle
